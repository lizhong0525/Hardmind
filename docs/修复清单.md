## 一、Hardmind 原始项目（app.py / templates）

### 安全类
| # | 问题 | 修复 |
|---|---|---|
| H1 | 「/static/」路由存在**路径穿越漏洞**：「/static/../app.py」可读取任意仓库文件 | 用 realpath 校验，仅允许 static 目录内文件，越界返回 403（集成测试覆盖） |

### 崩溃/卡死类
| # | 问题 | 修复 |
|---|---|---|
| H2 | SSE 推送时客户端断开 → BrokenPipeError 未捕获，处理线程崩溃 | 两个 stream 处理器均捕获断开异常并退出 |
| H3 | 对话/思考线程内任何未捕获异常（如 Ollama 长时间不可用后的解析失败）会导致 chat_active 永久为 True，前端永远 409「进行中」，只能重启服务 | 增加 abort 包装器：异常时复位状态、向前端推送错误与 done 消息 |
| H4 | call_ollama 对偶发网络错误零重试，且空响应直接当作内容使用 | 增加 1 次重试与空内容校验 |

### 测量/逻辑类
| # | 问题 | 修复 |
|---|---|---|
| H5 | **提示词污染（本项目最严重的问题）**：UCLA 前测提示词写「你心情总体不错」、后测写「你刚经历温暖对话，请按好转作答」，把结论塞进题目，前后测测的是提示词服从度 | 前后测统一为完全相同的中性指导语；代码注释说明盲测原则与遗留局限（独立调用无对话记忆，前后差异不声称疗效） |
| H6 | score_ucla 不校验分值范围，模型若返回 0/5 会直接污染总分 | 越界/非法分值视为无效施测返回 None |
| H7 | parse_ucla_response 逐行回退会把「题号」误当「分数」（「1. 3」解析成 1） | 优先按「题号. 分数」模式提取分数 |
| H8 | 孤独线索检测**只有英文词表**，而实际对话是中文——安慰模式（comfort mode）形同虚设 | 增加中文线索词表（一个人/没人说话/被冷落等） |
| H9 | 结束检测用子串匹配，英文「stopped」会误触发 stop | 英文关键词改为整词（词边界）匹配 |
| H10 | 相似度按空格分词，中文整句被当作一个词，重复检测对中文基本失效 | 中文按标点分词 |
| H11 | 每轮对话都调用一次 LLM 更新 Soul，30 轮带来 30 次额外模型调用，大幅拖慢运行 | 节流为每 5 轮更新一次 |
| H12 | build_think_prompt 硬编码「30 rounds」，与 total_rounds 配置脱节 | 动态使用 total_rounds |

## 四、已知设计权衡（非 bug，未改动）

- Hardmind 的 UCLA 评估为独立调用、不带对话记忆（架构限制），前后测
  差异不作为疗效声明；
- Hardmind 的话题池/开场语为英文、对话为中文，属原作者设计，保留；
- psybench E3 为小样本（n=3）配对设计，统计功效有限（已在技术报告中说明）。
